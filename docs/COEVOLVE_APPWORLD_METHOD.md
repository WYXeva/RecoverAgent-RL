## 必须贯通的机制

| 机制 | 本项目对应行为 |
| --- | --- |
| 初始任务合成 | 在训练来源环境真实探索，聚合同一初态的多次独立探索，抽象新目标与执行解法 |
| 遗忘信号 | 当前失败，且同一任务近期训练历史存在成功；保留历史窗口 |
| 边界信号 | 同一策略、任务和初态的一组真实采样同时包含成功和失败 |
| 稀有信号 | 累积动作模式频率低于阈值；频率和计数可核查 |
| 信号条件化 | 强模型仅依据合法历史总结失败/不稳定原因、探索目标及应避免的错误 |
| 多轮多步探索 | 对同一上下文运行独立环境探索分支，允许跨应用的公开API组合，保留动作/观察/分支ID |
| 任务抽象 | 由实际交互提取新查询、明确完成标准和不少于三步的成功执行依据；不套固定Gmail题型 |
| 执行验证 | 独立Solver从可重放初态执行新目标；控制侧语义验收和程序化终态/答案验收，失败与基础设施异常分别记录 |
| 训练中演化 | 当前Student组采样产生信号，按固定频率触发探索与任务入池；新任务从后续当前策略重新采样 |
| 数据隔离 | 生成/信号仅train来源；dev24及测试轨迹不进入生成或训练；参考解与验收信息不进入Student输入 |

## 复现口径与资源

实现目标是覆盖上述AppWorld方法机制。论文实验使用不同模型、探索服务、多GPU及更大规模；本轮保留用户选择的Qwen3.5-9B、现有32GB卡、既有S0/S1、32k、反馈15与最多16组、固定dev24。不能把本轮称为论文原设置或原成绩复现。

论文参考值与本轮运行值分别配置；论文未公开的历史窗口、动作模式定义、最小统计量等显式记录为实现选择。已有恢复SFT继续保留；CoEvolve生成与反馈循环接在本轮S2训练中，这一组合不是论文原始完整实验配方。

用户批准当前实例总计24小时，截止2026-11-10 14:12:31（UTC+8），包含已用时间；训练侧20万生成token和未知用量预留继续累计，不租机、充值或续费。旧探索与失败费用不清零。只以真实回执确认新任务合格、非零训练贡献和成功率变化。

当前状态：S1完成8步并保存重载；CoEvolve首段真实4候选/3合格，2个来自反馈。S1已采样生成任务2次；发现计数答案字符串/数字误拒绝后，在0个GRPO更新处停止并准备独立v2修复。原终态、答案和错误评分不改写；尚无S2更新或开发集结果。详见D097。

程序判据v2只对公开题意明确的单个数值做数值等价；其他答案保留精确JSON比较。原始与新revision均保留，修复不放宽目标业务终态。

## 真实运行发现的准入修复

新增`coevolve_goal_quality_v1`，在新Solver前检查未识别的明确单值请求，并用独立Teacher文本请求比较实际目标与原始任务/同源已有任务；仅措辞或输出格式变化不算新任务。原先的完整业务终态与答案判据不放宽。新配置为`configs/v2_round1_coevolve_quality_20261109.json`，旧源码锁保留。

既有池可通过`PYTHONPATH=src .venv/bin/python scripts/review_coevolve_pool.py --input review_input.json`进行只读资格审查。输入指定`source_run`、`source_code`、`deployment`、`s1_run`、`s0_checkpoint`及全新`output`路径；源码、来源摘要和原截止时间必须匹配。不启动Student、GPU或新任务执行。语义判定仍依赖强模型，保存完整依据，不当作形式证明；严格终态匹配仍可能排除其他合法解法。

# Shared Stage Validation：公开任务覆盖审计

本报告只使用官方 train 的公开 `specs.json.instruction`。没有读取 test 任务内容、隐藏 required_apps/required_apis、难度或标准答案。全池仅做ID/场景/原split与文件存在性统计。逐题说明和标签保留在私有 `runs/unified_split_20261027/private_task_coverage_v1.json`，公开统计见 [JSON](task_type_coverage.json)。

## 场景与应用

固定主 C 包含30个Task、30个Scenario；对90个官方train的30个场景逐一覆盖。每场景只取一个变体，不等于官方完整SGC，也不是未见场景泛化。完整候选C包含244场景，但其中测试场景内容未审阅，不能声称类型覆盖已确认。

| 公开任务文本中明确提及的应用 | C任务数 |
| --- | ---: |
| Spotify | 16 |
| Venmo | 7 |
| Phone | 3 |
| FileSystem | 5 |
| Simple Note | 4 |

应用计数可重叠；25题只有一个应用名称/代理关键词，5题提及多个应用。**这不是已验证的实际单应用/跨应用API需求**：Phone可能提供别的任务所需联系人，原始指令并不总会列出所有实际工具。Gmail、Amazon、Splitwise、Todoist没有在本train样本中匹配到明确应用名称，不据此断言它们从不涉及任何底层依赖，更不能用测试题内容补齐。

## 操作与依赖

| 确定性关键词标签 | C任务数 |
| --- | ---: |
| 查询 | 8 |
| 统计 | 7 |
| 创建/发送 | 6 |
| 修改 | 4 |
| 删除/取消 | 4 |
| 显式多步骤次序词 | 4 |
| 显式分页词 | 0 |
| 显式认证词 | 0 |

标签规则和SHA在代码及JSON；它们是可复现的**启发式词面证据**，可能漏标或误标，不能当作真实API步骤数或难度标注。比如 follow/like/play 等合法修改不都被通用modify关键词覆盖，含“所有”的任务也未必显式写分页。

所有90题的“实际需要分页”“实际需要认证”“实际跨应用数据依赖”保留unknown。不能把0个显式认证词解读成无需认证，也不能从初态只读工具探针推导完整任务依赖。模型收集后可以单独统计实际观察到的调用模式，但不得回过头按成功率重新选C。

## 缺口

- C覆盖全部30个合法训练场景，但不能覆盖全732池中的其余214个场景；其中19个dev场景与195个test场景不进入自定义参数训练。
- C词面标签集合覆盖当前train检测到的查询、统计、创建、修改、删除及显式多步骤类别，但标签计数不证明穷尽所有业务类型。A/B每类的分布另列于JSON。
- 认证、分页及跨应用依赖的可靠逐题标注尚缺；不得读取隐藏解法进行补全。
- C已被历史Teacher采集/开发过程接触，属于固定开发验证；只有重新训练并隔离C，才可比较新三阶段权重，仍不能声称无开发暴露。
